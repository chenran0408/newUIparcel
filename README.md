# 📦 取件码 Parcel

**自动解析快递短信和第三方通知，把取件码、地址、柜号直接摆到桌面小组件上。**

一个免费、开源、无广告的 Android 取件码助手。收到快递短信后自动提取「取件码 + 地址 + 柜号」，按地址分组展示，支持一键复制、桌面小组件实时刷新。

> 🟢 **默认完全本地。** App 内置的正则解析引擎全部在手机本地运行，不联网、不上传、不收集任何个人信息。
> 只有当你**主动开启「AI 解析」并填入自己的 API Key** 后，才会把**你指定的那一条短信正文**发送给你自己配置的服务商（详见 [🔐 隐私说明](#privacy)）。

## 📋 功能一览

### 📥 自动取件

- **系统短信自动读取**：新短信到达即解析，兼容国产 ROM 的多种短信 URI 与读取策略
- **第三方通知监听**：抓取微信、拼多多、抖音、小红书等 App 的「包裹已到」通知，自动存入取件码列表
- **多来源统一去重**：同一段文案在短信和通知里各出现一次，只会入库一次
- **三级解析策略**：完全解析 → 部分解析（保留原文可展开）→ 未识别进入失败排查页，取件短信不再「丢失」
- **验证码自动排除**：智能区分「取件码」和「凭验证码 123456」

### 🧩 更聪明的解析引擎

| 类别 | 已支持格式 |
|------|-----------|
| 取件码 | `61-4-0193`、`44-5-1001`、`6811-9770` 连字符码；`5-7447、5-7446` 多取件码；触发词 `凭` / `取件码是` / `件码` |
| 柜号 | `①号柜`、`③号柜` 圈号；`7号柜18-15格口`、`①号柜F38智能柜`、`③号柜B51智能柜` |
| 地址 | `苏席村25排`、`苏席村22排6号` 村排；`新柴市巷万家便利店` 便利店；`北街新华书店门口` 门口 |
| 触发词 | `前往` / `暂存` / `存放在` / `包裹在` / `派送至` |

- **驿站名优先显示**：地址优先展示驿站 / 便利店 / 超市名称，柜号单独成列
- **地址自动清理**：自动从地址里剔除柜号片段，不会出现「地址：3号柜」这种脏数据
- **自定义规则**：地址 / 取件码 / 柜号三类正则可自定义，还能设置「忽略关键词」直接跳过某些短信
- **规则导入导出**：规则集导出为 JSON 分享给朋友，一键导入合并

### 🗂 整理与查找

- **地址归类标签**：把多个地址归到同一个标签（如「公司」「家里」），地址旁一键打标
- **按柜号排序**：数字与圈号（①-⑳）都能正确排序，找柜子不用翻
- **时间筛选**：今天 / 3 天 / 7 天 / 全部
- **待取 / 历史双 Tab**：底部导航直达，角标显示待取数量
- **失败排查页**：没识别出来的短信集中查看，支持单条「重新解析」
- **日志页**：解析过程可追溯（自动脱敏，不记录短信正文与密钥）

### 🖼 界面与个性化

- **5 套主题**：跟随系统 / 日间明亮 / 经典深色 / 翡翠夜景 / 极光紫罗兰
- **关怀模式（老人模式）**：大字号 + 独立响应式布局，触控目标放大到 56dp
- **自定义壁纸**：本地图片或 https 图片链接，可调模糊 / 遮罩 / 渐变 / 亮度 / 对比度 / 铺放方式
- **导出取件卡片**：把取件码画成高清 PNG 卡片存相册，或复制成文本清单发给家人
- **整站备份**：设置 + 规则 + 地址映射导出为一份 JSON

### 🧠 AI 大模型解析（可选）

- **14 家服务商预设**：DeepSeek、通义千问、智谱 GLM、豆包、Kimi、混元、MiniMax、百川、阶跃、硅基流动、火山方舟、NVIDIA NIM + 自定义 OpenAI 兼容接口
- **三种解析策略**：正则独占 / AI 优先（失败降级正则）/ AI 独占
- **后台自动解析**：开启后只处理**启用之后**的新消息，旧短信不会回灌
- **幂等账本**：按正文 SHA-256 指纹去重，同一条短信只会被提交一次
- **连通性测试**：测试前先测延迟，报错按 401 / 404 / 超时分类提示
- **成本控制**：每日请求额度上限、仅 Wi-Fi 解析开关
- **密钥安全**：API Key 存进 Android Keystore（AES/GCM），不进配置文件、不进备份

### 📱 系统集成

- **5 种桌面小组件**：标准 / 大号 / XL + MIUI 专用双规格
- **通知使用权 + 快捷设置磁贴**：一键开关监听
- **开机自启**：重启后自动恢复通知监听
- **后台保活**：开启通知监听后小组件实时更新
- **身份码直达**：淘宝（tbopen）、拼多多（pinduoduo）原生 App 跳转

## 🔑 权限说明

App 需要的每一项权限都有明确用途，可以按需逐个开启：

| 权限 | 用途 | 不开的后果 |
|------|------|-----------|
| 读取短信 / 接收短信 | 自动解析快递短信 | 需要手动逐条录入 |
| 通知使用权 | 监听第三方 App 通知 + 后台保活 | 无法抓取微信 / 拼多多等通知 |
| 通知（POST_NOTIFICATIONS） | 发送解析完成提示 | 无提示，不影响主功能 |
| 前台服务 | 保持小组件数据同步 | 小组件可能延迟刷新 |
| 忽略电池优化 | 后台持续监听 | 进程容易被杀，小组件不更新 |

**国产 ROM 额外注意**

- **小米 / 澎湃**：设置 → 应用设置 → 应用管理 → 取件码 → 其他权限 → 通知类短信 → **始终允许**；并在「自启动」里开启
- **华为 / 荣耀**：关闭「应用启动管理」中对本 App 的自动管理
- **OPPO / vivo / _REALME**：电池设置里选择「不限制后台行为」
- 通用：在系统设置的「电池 / 耗电管理」中对本 App 设为**不限制**，并允许自启动

<a id="privacy"></a>

## 🔐 隐私说明

- **默认不联网。** 全 App 唯一的网络代码在 `util/ai/AiClient.kt`，只有你开启 AI 解析并填入 API Key 后才会被调用。
- **不上报、不统计、无广告 SDK。**
- **不收集个人信息。** 短信、通知内容、规则、地址映射全部只存在你本机的 SharedPreferences / Room 数据库中。
- **启用 AI 后的数据流**：只有你手动触发解析（或开启自动解析后的新消息）的**那一条短信正文**会被发往你填写的 API 地址。**内容不经过本项目作者。**
- **API Key 加密存储**：使用 Android Keystore 的 AES/GCM 加密，不写入明文配置，整站备份导出时也会自动剥离。
- **日志脱敏**：日志不会记录短信正文、通知正文、API Key、Authorization 头。
- **仅 HTTPS**：AI 接口强制要求 https，App 不开启明文流量。
- **想完全不用网络**：不开启 AI 解析即可，App 会一直停留在纯本地正则模式。

## ❓ 常见问题

<details>
<summary><b>1. 桌面小组件在哪？</b></summary>

长按桌面空白处 → 小组件 → 找到「取件码 / Parcel」。一般在**全部卡片列表的最底部**，或者折叠在「插件」分类里。
</details>

<details>
<summary><b>2. 小组件不更新？</b></summary>

通常是后台进程被杀了。开启**通知使用权**可以显著提升存活率；再配合系统「自启动」+ 电池「不限制后台行为」，最后删除并重新添加小组件。
</details>

<details>
<summary><b>3. 某些快递短信识别不了（没有发送者号码，5G 消息）？</b></summary>

这种短信目前有三种处理方式：

1. 在系统短信设置里关闭 **[服务信息] / [5G 信息]** 的「通过移动数据或 WLAN 接收商家信息」
2. 开启「监听第三方 App 通知」，配置并监听对应的网络短信通知，自动存入自定义取件短信
3. 在失败排查页点「原文」查看完整短信，手动抄取件码
</details>

<details>
<summary><b>4. 完全没收到短信？</b></summary>

- 复制取件码或整段短信，点底部 **+** 号按钮，自动粘贴导入
- 或联系快递客服，把取件通知方式改成短信通知
</details>

<details>
<summary><b>5. 怎么和家人共享？</b></summary>

- 分享取件信息：**导出取件卡片**生成图片，或**复制文本清单**
- 分享解析规则：菜单 → 导出规则 → 生成 JSON → 对方菜单 → 导入规则
</details>

<details>
<summary><b>6. AI 解析要花钱吗？</b></summary>

取决于你选择的服务商和用量。App 内置了**每日请求额度上限**（默认 50 次）和**仅 Wi-Fi 解析**开关来帮你控成本。也可以完全不用 AI，正则引擎已经覆盖了绝大多数国内快递短信。
</details>

<details>
<summary><b>7. 识别错了怎么办？</b></summary>

- 单条修正：录入页 / 规则页 → 添加自定义取件码 / 柜号 / 地址规则
- 整体忽略：规则页 → 添加忽略关键词，含该词的短信直接跳过
- 想找回漏网的：失败排查页 → 查看原文 / 重新解析
</details>

<details>
<summary><b>8. 怎么让取件码按柜号排？</b></summary>

设置 → 显示偏好 → 打开「按柜号排序」。圈号（①-⑳）也支持。
</details>

## 🛠️ 开发构建

### 环境要求

- Android Studio Hedgehog (2023.1) 或更新
- JDK 11
- Gradle 8.13（由 wrapper 自动下载）
- Android SDK 35

### 常用命令

```bash
# 调试包
./gradlew.bat assembleDebug        # Windows
./gradlew assembleDebug            # macOS / Linux

# 发布包（需先配置 key.properties）
./gradlew assembleRelease
```

### 签名配置

Release 构建需要在**项目根目录**放一个 `key.properties`（已被 `.gitignore` 忽略，不要提交）：

```properties
keyAlias=xxx
keyPassword=xxx
storeFile=xxx.jks
storePassword=xxx
```

缺少该文件时 `assembleRelease` 仍可运行，但产物**未签名**。

### 仓库约定

- **路径别名**：`K` = `app/src/main/java/com/chenran/parcel`
- **视觉令牌唯一出处**：`ui/theme/ParcelPalette.kt`；面板组件唯一出处 `ui/components/Surface.kt`。`ui/` 下禁止硬编码 `Color(` / `sp` / `dp`（`ui/theme/` 除外）
- **改动流程**：每轮遵循 `docs/SOP.md` 的「勘察 → 实施 → 静态验证 → Review → 快照」循环，并生成 `docs/snapshots/round-N-*.md`
- **版本发布**：改 `app/build.gradle.kts` 的 `versionName` / `versionCode` → 跑 `1build.sh` → 校验 `checkApk.sh` → 发 Release。`1build.sh` 会自动同步本 README 的版本号

### 已知状态

> R16–R23 的改动目前是**静态交付**（已完成签名 / 依赖 / 广播 / Manifest 静态核对），**尚未执行完整 Gradle 构建与真机验收**。
> 详见 [`docs/GOAL.md`](docs/GOAL.md) 的 G6 标准。
